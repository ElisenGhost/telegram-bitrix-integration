# Telegram ↔ Bitrix24 Smart Process Integration (Node.js)

Это готовый проект, который:
1. Приходит на webhook от Telegram (когда пользователь пишет боту).
2. Создаёт или находит Smart Process (SPA) элемент в Bitrix24 и сохраняет в нём chat_id Telegram.
3. Добавляет сообщение пользователя как комментарий в timeline карточки обращения.
4. Слушает исходящие события от Bitrix (outbound webhook) о новых комментариях и отправляет их пользователю в Telegram.

--- Важно: --- 
Этот проект — минимально рабочий пример для локальной/серверной настройки. В продакшне используйте БД, очереди и безопасное хранение токенов.

## Что внутри архива
- server.js — основной сервер.
- package.json — зависимости.
- .env.example — пример переменных окружения.
- mapping.json — простая локальная "база" для сопоставления chat_id ↔ item_id (начально пустая).

## Быстрая инструкция «как для ребёнка»
1. Скопируй этот архив на сервер (VPS) или на компьютер, где будет работать бот.
2. Распакуй: `unzip telegram-bitrix-integration.zip` и зайди в папку `cd telegram-bitrix-integration`.
3. Скопируй `.env.example` в `.env`:  
   `cp .env.example .env`  
   и впиши свои данные (см. комментарии в файле).
4. Установи Node.js (рекомендуемая версия >=18) и затем зависимости:  
   `npm install`
5. Запусти сервер:  
   `npm start`  
   или для разработки: `npm run dev` (если установлен `nodemon`).
6. Сделай публичный HTTPS URL для сервера (ngrok / VPS с certbot / облачный провайдер). Telegram требует HTTPS для webhook.

## Шаги в Bitrix24 (где нажимать — подробно)
### A. Создать поле в Smart Process
1. Открой Bitrix24 как администратор.
2. Перейди в раздел «CRM» → «Смарт процессы» (иногда называется «Динамические сущности»).
3. Открой нужный смарт-процесс или создай новый.
4. Нажми «Настройки полей» → «Добавить поле» → Тип — строка.  
   Дай имя: `UF_CRM_TELEGRAM_CHAT_ID` (или похожее). Сохрани.

### B. Incoming Webhook (входящий, для REST-запросов из сервера в Bitrix)
1. В админке Bitrix найди «Приложения» → «Вебхуки» → «Входящие вебхуки».
2. Нажми «Добавить» → Выбери права: `crm`, `lists`, `user` — хватит для создания элементов и комментариев.
3. Система выдаст URL вида: `https://yourcompany.bitrix24.ru/rest/<user_id>/<webhook_key>/`
   Скопируй `user_id` и `webhook_key` в файл `.env` как `B24_WEBHOOK_USER` и `B24_WEBHOOK_KEY`.
4. В `B24_DOMAIN` укажи `yourcompany.bitrix24.ru`.

### C. Outbound Webhook (исходящий — когда в Bitrix добавляют комментарий)
1. В панели разработчика Bitrix (Dev или Приложения) найди «Outbound webhook» или «Исходящие вебхуки».
2. Создай новый исходящий вебхук и подпишись на событие добавления комментария в Timeline. В Bitrix это может называться:
   `OnCrmTimelineCommentAdd` или похожее (в зависимости от версии).
3. В качестве URL укажи `https://<ваш-public-url>/bitrix/outbound` (например, `https://example.com/bitrix/outbound`).
4. Установи секрет/токен в настройках исходящего вебхука — запомни его (используй для проверки).

## Шаги в Telegram
1. Создай бота через BotFather и получи `TG_TOKEN`.
2. Установи webhook:  
   `curl -F "url=https://<ваш-public-url>/telegram/webhook" https://api.telegram.org/bot<TG_TOKEN>/setWebhook`
3. Проверь, что Telegram сообщает успех.

## Как протестировать (пошагово)
1. Напиши боту в Telegram: любое сообщение.
2. Сервер получит update, создаст SPA элемент (если не найден) и добавит комментарий в карточку.
3. Открой карточку в Bitrix — увидишь комментарий от пользователя.
4. Напиши ответ прямо в карточке (добавь комментарий). Если настроен Outbound webhook — комментарий должен прийти в вашу `/bitrix/outbound` и сервер отправит сообщение пользователю в Telegram.

## Что делать если что-то не работает
- Проверь логи сервера (stdout).  
- Убедись что webhook Telegram настроен на правильный URL и сервер доступен по HTTPS.  
- Убедись что incoming webhook Bitrix корректный (user и key в .env).  
- Убедись, что `SPA_TYPE_ID` — это корректный entityTypeId вашего smart process (в Bitrix это число).

## Примечания по безопасности и доработке
- В примере используется локальный JSON-файл `mapping.json` для сопоставлений. В продакшне — используйте Postgres/MySQL/SQLite.
- Добавьте проверку подписи/токена у исходящих запросов от Bitrix (application_token).
- Обрабатывайте файлы, изображения и т.д. — это можно добавить отдельно.
